# Bundle optimisation — August 2026

All figures are **measured**, not estimated. Reproduce with
`bash scripts/bundle-baseline.sh <label>`.

## Which number matters

Total emitted JS is the wrong metric for code-splitting. Moving a library
behind `next/dynamic` leaves the total unchanged — it actually grows slightly,
from the extra loader chunks — while cutting what a route downloads before it
can paint. So the headline below is **per-route first-load JS**.

Next 16 with Turbopack no longer prints per-route sizes, so the script derives
them from the scripts each prerendered route's own HTML references. That is
exactly the set a browser fetches on first load.

| `/register` | 589.0 KB | 472.3 KB | **−116.7 KB (−19.8%)** |
| `/dashboard` | 876.5 KB | 787.2 KB | **−89.3 KB (−10.2%)** |
| `/dashboard/finance/pnl` | 888.9 KB | 776.4 KB | **−112.5 KB (−12.7%)** |
| `/dashboard/requirements` | 829.2 KB | 830.6 KB | +1.4 KB |

All gzipped. `/dashboard/requirements` moving +1.4 KB is loader-chunk noise; see
"recharts" below for why it was expected not to move.

Total emitted JS rose 2092.0 → 2129.9 KB gzipped. That is the cost of the extra
loader chunks and is the expected trade: every route now downloads less.

## What actually moved the numbers

| Change | Measured effect |
|---|---|
| recharts behind `next/dynamic` (2 sites) | −89.3 KB `/dashboard`, −112.5 KB `/pnl` |
| lottie-react behind `next/dynamic` | −77.4 KB `/register` |
| framer-motion off the auth path (CSS instead) | −39.5 KB `/login` and `/register` |

## What saved nothing, and why

Two items the plan expected to be wins were measured at **0 KB**:

- **Removing 4 unused `@fullcalendar` packages.** The plan called this the
  single largest free win at ~150–200KB. A package that is never imported never
  enters the bundle, so removing it cannot shrink one. Still worth doing for
  install size, CI time and supply-chain surface — just not for shipped bytes.
- **Deleting two 1.2MB PNGs.** Both were unreferenced, so Next never bundled
  them and no user ever downloaded them. They needed deleting, not converting
  to WebP; the sharp conversion script the plan budgeted was unnecessary.

The lesson in both cases: *unused* is not the same as *shipped*.

## Also fixed

**Background polling.** 11 of 12 polling queries lacked
`refetchIntervalInBackground`, so a hidden tab kept hitting the API every
10s–2min indefinitely. `src/tests/polling-config.test.ts` now fails the build if
a new polling query skips the flag.

## Not done, and why

- **date-fns → dayjs consolidation.** Measured the actual cost of the date-fns
  subset in use: **6.9 KB gzipped** (22.9 KB minified), under 1% of the
  requirements route. Against that, 26 call sites and 15 distinct `format`
  token strings needing hand translation (`yyyy` → `YYYY`, `dd` → `DD`), where a
  mistake produces a *wrong date* rather than an error. Bad trade. The plan
  explicitly sanctioned skipping this one.
- **`PnLTab` chart extraction.** Already behind `next/dynamic`
  (`RequirementDetailsPage.tsx:39`), so recharts was never on that route's first
  load. Measurement confirms it: the route moved +1.4 KB, i.e. noise.
- **Converting `public/fonts/Manrope-*.ttf` to WOFF2.** They are not
  page fonts — the page uses `next/font/google`. These are fetched on demand by
  jsPDF for report generation, and jsPDF cannot read WOFF2.
- **Nonce-based CSP.** `next.config.mjs` still needs `'unsafe-inline'` for
  Next's inline scripts. Separate piece of work.
- **List virtualisation.** Tables render full arrays. Not worth the complexity
  at current page sizes; revisit if a list regularly exceeds ~200 rows.
- **Moving the `use client` boundary.** 113 files carry the directive and
  `dashboard/layout.tsx` forces the whole tree client-side. This is the single
  biggest remaining lever on `/dashboard` — an architecture change, tracked in
  Phase 7, not a bundle tweak.
